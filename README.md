# memory-chain

以**事件链**的思路对会话记忆进行总结归纳——把 AI 会话压缩成结构化交接笔记，按事件链归档，新会话读回即可接着干。

一个纯文件方案：不依赖插件、不依赖数据库、不依赖向量检索。

> 一作 / 实现：鲸跃　·　上传与验收：Fatcat515

---

## ⚠️ 先读这段（隐私与数据范围）

本工具会读取本机 DSH 会话的**原始记录全文**：

```
$DSH_HOME/sessions/<工作区目录名>/<会话id>/session.v4.jsonl.zstd
```

包含用户输入、模型回复、工具调用与结果。使用前请确认：

- 这些会话是**你自己的**；
- 共享机器上不要对他人会话使用；
- 默认只读你点名的那一段会话，不主动遍历或窥探；
- 交接笔记是**明文 markdown**，不加密 —— 凭据、密钥、客户隐私不要写进去。

## 安装

下载 `memory-chain.zip` 解压，把里面的 `memory-chain/` 整个目录复制到：

```
%USERPROFILE%\.agents\skills\memory-chain\
```

**不需要重启**，技能是纯文件读取，复制完即可用。

## 用法

| 你说 | 它做什么 |
|---|---|
| 「交接一下」/「准备交接文件」 | **正式**：写完整六段笔记，归属到某条链 |
| 「压缩一下」/「记一下」 | **轻量**：写三五行散条，不建链 |
| 「接上次」/「读交接笔记」 | 读链目录里文件名最大的那份，复述目标、进度、下一步 |
| 「@某段旧会话，继承过来」 | 直读会话原始记录，筛出真人输入再压缩 |

## 为什么不用 `@` 快照

实测一段 2137 条事件的旧会话里，65 条 `user/message` 中有 **32 条（49%）是系统注入** —— 时间戳、运行时上下文、技能目录变更、后台任务通知。它们被当成「用户消息」存着，但**不是用户说的话**。

对着快照做压缩，就会把系统注入当成用户的决定记下来。按 `data.source.kind === "user"` 这个结构化判据筛，才只拿到真人输入。
