# memory-chain

> 把 AI 会话压缩成结构化交接笔记，按**事件链**归档；新会话读回即可接着干。
> 一个纯文件方案：不依赖插件、不依赖数据库、不依赖向量检索。

版本 **v1** · MIT · 作者：鲸跃（一作）/ JackDawn（裁决与验收）

---

## 它解决什么问题

LLM 会话的上下文会满。满了就得开新会话，于是：

- 上一轮谈定的方案没了；
- 做到一半的活不知道做到哪；
- 踩过的坑再踩一遍。

已有的解法各有代价：全量塞回去烧钱且降智；向量检索把「结论」和「过程」混着召回；
自动摘要看起来都对，但**每条都不带出处**——三个月后读到，只能选择相信或不信，而两条路都不对。

memory-chain 的做法是：**把上下文扔掉，只留结论，并且给它一个能查回去的地址。**

---

## 三个核心约定

**1. 一条事件链 = 一个目录**

```
$DSH_HOME/handoff/<工作区slug>/
    2026-10-23_handoff-system/          ← 一条叙事链
        2026-10-23_2305_handoff-layout_1e40c09a.md
        2026-10-23_2338_chain-dirs_1e40c09a.md
    2026-10-21_stellaris-mod/            ← 另一条链，互不干扰
    legacy-2026-10-23.md                 ← 未归链的旧账
```

**2. 一次交接 = 一个文件，只增不改**

命名 `YYYY-MM-DD_HHMM_<主题>_<会话id前8>.md`。时间前缀保证「文件名排序 = 时间排序」，
所以「取最新」只要取文件名最大的那个——不需要读 mtime（批量改名会把 mtime 全刷成同一时刻）。

多个会话并行写入时**零冲突**：各写各的文件，谁也不用等谁。

**3. 链条靠指针串，不靠把历史抄一遍**

每份笔记顶部有一行 `继承自`：同链内写链名，跨链写 `<链名>/<文件名>`，混合继承用 ` + ` 连。
新笔记只写「仍然有效的前提」+「这次的新进展」，不复述上一条的全过程。

## 安装

把整个 `memory-chain/` 目录复制到：

```
%USERPROFILE%\.agents\skills\memory-chain\
```

**不需要重启**，技能是纯文件读取，复制完即可用。

### 可选：让它自动生效

把 `AGENTS.md.example` 复制成 `%USERPROFILE%\.dsh\AGENTS.md`（每轮自动注入，约 1KB）。
这样每个新会话开局就知道有这么个机制、什么时候该用，不用你先说触发词。

## 用法

| 你说 | 它做什么 |
|---|---|
| 「交接一下」/「准备交接文件」 | **正式**：写完整六段笔记，归属到某条链 |
| 「压缩一下」/「记一下」/「存个档」 | **轻量**：写三五行散条，不建链 |
| 「接上次」/「读交接笔记」 | 读链目录里文件名最大的那份，复述目标、进度、下一步 |
| 「@某段旧会话，继承过来」 | 直读会话原始记录，筛出真人输入再压缩（模式三） |

正式笔记的六段：**任务目标 / 当前进度 / 关键决策 / 涉及文件 / 下一步 / 坑与禁忌**。

两个容易被忽略的字段：

- **涉及文件**必须写**绝对路径**。「在桌面上有个快捷方式」这种写法，下一个人会把桌面翻一遍还是找不到。
- **下一步**每条带来源标记：`[新]` 是本轮产生的，`[遗留·MM-DD起]` 是上次就挂着、至今没结的，并补一句「卡在…」。不标来源，几轮之后会攒成一堆不知道什么年代的僵尸待办。

## 工具：read-session

`tools/read-session.mjs` 用来直读 DSH 会话原始记录（多帧 zstd 压缩的 jsonl），
**零第三方依赖**（只用 `node:fs` / `node:path` / `node:zlib`）。

```bash
read-session.cmd list                    # 列出本机会话：id / 大小 / 时间 / cwd / 文件路径
read-session.cmd dump <file> --out o.txt # 解压并按来源分类，输出六段报告
read-session.cmd schema                  # 列出全部记录类型的字段结构
```

`.cmd` 是 Windows 包装器（自动找 node：先 PATH，再用 DSH 自带 runtime）。其他平台直接 `node read-session.mjs`。

**为什么需要它**：`@` 引用的会话快照只有 `role + text`，没有工具调用。
实测一段 2137 条事件的旧会话里，65 条 `user/message` 中有 **32 条（49%）是系统注入**——
时间戳、运行时上下文、技能目录变更、后台任务通知。它们被当成"用户消息"存着，**但不是用户说的话**。
对着快照做压缩，就会把系统注入当成用户的决定记下来。

按 `data.source.kind === "user"` 这个结构化判据筛，才能只拿到真人输入。

## ⚠️ 隐私与数据范围

**这个工具会读取本机 DSH 会话的原始记录**：

```
$DSH_HOME/sessions/<工作区目录名>/<会话id>/session.v4.jsonl.zstd
```

这些文件包含**完整的历史对话原文**——用户输入、模型回复、工具调用与结果。

使用前请确认：

- 这些会话是**你自己的**；
- 若在共享机器上，不要对他人会话使用；
- 默认行为是**只读用户点名的那一段会话**，不主动遍历或窥探；
- 压缩生成的交接笔记是**明文 markdown**，落在 `$DSH_HOME/handoff/` 下，**不加密**。
  凭据、密钥、客户隐私不要写进笔记——真要记，写「密钥在 X 处」而不是密钥本身。

## 已知限制

- **不自动触发**。技能按需加载，得有人说一句，或由 agent 主动建议。
  想全自动（上下文快满时自己落盘）需要监听 token 用量，那得写插件，不在本项目的范围。
- **压缩是转述，不是原文**。所以流程里有一条红线：写完必须让用户扫一眼要点，那是唯一的失真兜底。
- **文件策略收紧时**（DSH 的 `workspace-write`），`~/.dsh` 在工作区外，写入会被沙箱拒绝。
  SKILL.md 里内置了三级回退：`DSH_HANDOFF_DIR` → `$DSH_HOME/handoff` → `<工作区>/.handoff`。
- 会话存储格式是 `session.v4`。上游若改格式，`read-session` 需要跟着改（脚本内已有正则兜底判据）。
